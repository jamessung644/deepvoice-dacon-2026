# v7 · 보관 제출본 구조

2026-09-11의 보관 ZIP 실행 코드·모델 어댑터·구성 검사를 바탕으로 정리했습니다. 2026-10-01 공개 자료는 경로·계정 정보와 실제 가중치를 제외합니다.

## 경로와 집계

| 경로 | 모델 / 입력 | 시간창과 집계 |
|---|---|---|
| 음성·음악 존재 | PANNs Cnn14 / 원음 16 kHz → 32 kHz | 약 4.0375초 + 끝창; 관련 클래스와 창의 최대 확률 |
| 음성 진위 | Forensics WavLM-large + AASIST graph pooling + 분류기 / 원음 | peak 정규화, 5초 + 끝창, 짧으면 반복; 활성창 최대 FAKE |
| 음악 분리 | HTDemucs | 비보컬 성분 합산 후 16 kHz |
| 분리 음악 진위 | LogSpec ResNet V1 | 약 4.0375초 창, 최대 8개; 확률 평균 |
| 원음 음악 진위 | LogSpec ResNet V5 sqrt/equal | 동일 창 정책; 두 모델 확률을 60:40 결합 |

Forensics 음성 모델은 24층 WavLM-large(hidden 1024, 16 heads) 기반입니다. 음성 활성 조건은 정규화 전 RMS ≥ 1e-5이고, 비활성 창은 0입니다. 음성 FAKE는 `1 − sigmoid(REAL logit)`이며 FP32로 실행합니다.

음악은 기본 50% 겹침창을 만들고 8개를 넘으면 시작~끝의 8개 위치로 제한합니다. 짧은 창은 0패딩합니다. 따라서 긴 파일 전체를 빠짐없이 평가하지 않으며 **시간창 8개와 독립 평가 8회는 다릅니다**. 일반 스테레오는 평균하지만 위상 상쇄가 심하면 가장 에너지가 큰 채널을 선택합니다.

## 실제 실행식

```text
raw_music = 0.6 × sqrt_CNN + 0.4 × equal_CNN
MUSIC_FAKE = 0.5 × stem_CNN + 0.5 × raw_music
           = 0.5 × stem_CNN + 0.3 × sqrt_CNN + 0.2 × equal_CNN
FILE_FAKE = max(VOICE_PRESENT × VOICE_FAKE,
                MUSIC_PRESENT × MUSIC_FAKE)
```

FILE 결합에는 반올림 전 확률을 사용하고 CSV 다섯 출력은 소수점 10자리로 반올림합니다. v7 전환은 v6 대비 음악 결합 비율 변경이며 새 학습이 아닙니다. 음성 모델에는 분리 보컬이 아닌 원음을 넣습니다.

PANNs 존재 검출을 먼저 실행하고 모델을 해제한 뒤 파일별 분리·진위 경로를 계산합니다. README 그림은 데이터 흐름이지 동시 실행 구조가 아닙니다.

## 공개 코드의 범위

공개된 모델 정의는 현재 프로젝트 소스의 선별 사본입니다. 특히 일부 안전성 검사·결정적 pooling은 이후 개발을 포함합니다. **공개 소스가 과거 제출 ZIP 전체의 바이트 단위 스냅샷이라는 뜻은 아닙니다.** Forensics·PANNs·HTDemucs 구현과 나머지 가중치는 제외했습니다. PANNs 가중치 1개만 원본 고지를 갖춰 별도 Releases에 제공하며, 이 코드와 파일만으로 5출력 전체를 실행할 수 없습니다.
